A set of keys, handed in at the counter, needs a description before it can
become a case. "Black keys" is not one: half the keys handed in on any
given week are black, and a description that matches half the shelf
matches none of it. Last week's hand-in point solved for getting an object
to the Office at all. This week's question is what happens once it
arrives: can you write an object down so a stranger knows it?

## What a free-text box leaves out

Given an empty box and told to describe a set of keys, most people write
what they notice first, and everyone notices something different: the
number of keys, the keyring, a scratch, a fob shaped like a fish. None of
that is wrong, and none of it is comparable across two hundred other
descriptions written the same way. A record that a stranger has to
interpret rather than match is only useful to the person who wrote it.

## Classification decides what can be found

Bowker and Star's *Sorting Things Out* argues that every classification
scheme makes some things easy to find and others invisible by design —
there is no neutral way to sort. A scheme built around "type of key" will
lose the set with the distinctive fob; one built around "distinguishing
feature" will lose the plain set with nothing to distinguish it. The
Office's intake form has to pick, and whatever it picks will fail some
future case in a predictable way. The point of drafting it in the open is
finding out which failure the class can live with.

A record is only as good as a stranger's ability to match it against the
object in front of them, months later, with no memory of writing it.

## Reading

Bowker & Star (1999), *Sorting Things Out: Classification and Its
Consequences*, MIT Press. Read the introduction for the argument that
classification always has a cost, paid by whatever the scheme leaves out.

## What the Office gains

The intake form: a fixed set of fields every deposit is described against
from here on, replacing whatever each student would otherwise have written
by hand. This week's exercise on the counter is the reason: free text
matches everything or nothing, and a form built from a handful of fields
gets to one match faster.
